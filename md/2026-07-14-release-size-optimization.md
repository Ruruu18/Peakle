# Release Size Optimization

**Project:** Peakle  
**Date:** July 14, 2026  
**Status:** Configuration implemented and validated; native build deferred

## Objective

Reduce the application size downloaded by users without changing Peakle's visual design, supported features, or normal runtime behavior.

## Implemented optimizations

### Android release shrinking

Added the Expo `expo-build-properties` package and configured the Android release build in `app.json` to use:

```json
{
  "android": {
    "enableMinifyInReleaseBuilds": true,
    "enableShrinkResourcesInReleaseBuilds": true
  }
}
```

- R8 minification removes or reduces unused Java and Kotlin code in release builds.
- Resource shrinking removes Android resources that are not used by the final application.
- These options apply only to production builds and do not change the UI implementation.

### Android App Bundle distribution

Created `eas.json` with a production profile that explicitly generates an Android App Bundle:

```json
{
  "build": {
    "production": {
      "android": {
        "buildType": "app-bundle"
      }
    }
  }
}
```

An `.aab` lets Google Play generate a device-specific download containing only the architecture, screen-density resources, and other files needed by that user's device. This is normally smaller than distributing a universal APK.

### Image optimization

The Google sign-in mark was reduced from `200 × 204` pixels and `33,661` bytes to `96 × 98` pixels and `10,227` bytes.

- File-size reduction: `23,434` bytes, or approximately `69.6%`.
- The image is displayed at `20 × 20` logical pixels, so the optimized source retains sufficient resolution for high-density mobile screens.
- Its format and transparency remain unchanged.

The `512 × 512` ball artwork was reviewed but intentionally left unchanged. It is rendered as large as `190 × 190` logical pixels in the authentication artwork, so reducing it could cause visible softness on high-density devices.

## Dependency review

The installed native dependencies were checked against their usage in the application. Each major dependency currently supports an active feature, including:

- local device storage;
- navigation;
- Supabase authentication and data access;
- Google authentication;
- location lookup;
- team image selection;
- browser-based OAuth;
- SVG avatar rendering.

No active dependency was removed because doing so would remove or break application functionality. Development dependencies were also left in place because they do not ship as part of the users' production download.

## Build status

No APK, AAB, IPA, or native application build has been generated. A temporary minified Android JavaScript export was measured before the instruction to defer builds; it contained a `3.76 MB` Hermes bundle and approximately `390 KB` of Ionicons font data. That temporary output is outside the project in `/private/tmp` and is not a distributable application build.

No additional build or export command was run after the build restriction was given.

The exact Google Play and App Store download-size improvement cannot be measured until production artifacts are approved and generated. Android size should be measured from the device-specific downloads produced from the release `.aab`, rather than from a universal development APK.
